# 第22章　机械手臂与炉管：预测性维护的微秒秒表

## 情境 71　机械手臂(EFEM)马达电流突发性微幅飘移(Current Drift)的预测性在线维护
**背景**：300mm 晶圆厂光罩传输区的 EFEM(Equipment Front End Module)机械手臂，每天搬运上万片晶圆进出 Load Port，伺服马达电流由 SECS/GEM 每 200ms 上报一次。
**问题**：凌晨 03:17，某支 SCARA 手臂第 4 轴的负载电流基线在 12 小时内悄悄从 2.31A 漂移到 2.58A——仅 0.27A，远在告警阈值之内，传统 SPC 看不出来。但这是谐波减速机(Harmonic Drive)波发生器润滑膜开始崩解的死亡前兆，再放任 6 小时就会在搬片途中卡死，把一片正在交接的 EUV 光罩级晶圆甩落，瞬间 Scrap 数百万美元。
**需要的技能**：伺服马达电流信号处理、谐波减速机失效模式分析、时间串行趋势侦测、SECS/GEM 数据采集。
**开源工具**：River(在线学习漂移侦测)、InfluxDB(时序库)、scikit-learn(IsolationForest)、Grafana。
**用到的 Agent 特性**：龙虾 OpenClaw 的子 Agent 常驻订阅 InfluxDB 电流流，用 River 的 ADWIN 漂移算法在线比对每轴基线；侦测到第 4 轴 0.27A 缓慢漂移后，本地脚本立即从 ClawHub 拉「谐波减速机寿命残值估算」技能插件算出剩余 5.8 小时安全窗，并通过 Multi-Channel Gateway 同步把告警 + 残值曲线推到设备工程师的 Teams、值班长的 LINE、以及 MES 维护工单系统，附上「建议在 04:00 换班空档运行 PM」的时间建议。
**没有 Agent 的窘境**：人类值班只盯红黄灯告警，0.27A 的漂移永远不会触发红灯；等到手臂卡死甩片，FA 工程师才被 call 起床，边揉眼睛边查 log，MTTR 动辄 90 分钟，而那片光罩级晶圆早已报废。
**效益**：未报警的微飘移从「肉眼不可见」变成「5.8 小时前精准预警」；非计划停机 → 计划内换班 PM，单次避免 Scrap 约 240 万美元，手臂可用率(Availability) +0.4%。

> 💡 君之一席话
> 「真正杀死产线的，从来不是那些会闪红灯的故障，而是那些安静地躲在阈值里、慢慢长大的 0.27 安培。」

> 🔍 高端点评──道路在哪里
> 这个案例把龙虾从「告警转发器」推向「残值精算师」——它指向的实务道路是 Agent 直接持有设备的寿命模型，并把「还剩多久」翻译成调度语言。落地的信任边界在于：当 Agent 说「再撑 5.8 小时」时，谁敢真的让手臂再跑 5 小时？这需要残值估算的信赖区间可被工程师审计，否则没人敢把急停权交给一条 0.27A 的曲线。

## 情境 72　原子层沉积(ALD)前驱物气阀毫秒级切换延迟的在线晶圆动态救灾
**背景**：ALD 制程靠前驱物气阀(Precursor Valve)与吹净阀以毫秒级精度交替开关，逐层沉积原子层薄膜，气阀动作时间由设备 trace data 以 1kHz 采样。
**问题**：某腔体 A 前驱物阀的打开响应从稳定的 8ms 突然劣化到 14ms，虽然仍在规格 20ms 内，但每个 ALD 循环多吃 6ms 残留气体，导致膜厚均匀度(Uniformity)在第 137 片晶圆开始系统性偏厚 0.3nm。当前批还有 18 片在腔体内排队，再不处理就是整批 25 片 0.3nm 超规报废。
**需要的技能**：ALD 沉积化学动力学、气阀电磁致动器诊断、即时 trace data 分析、制程配方动态补偿。
**开源工具**：Apache Kafka(trace 串流)、Telegraf、Faust(串流处理)、Prometheus。
**用到的 Agent 特性**：龙虾子 Agent 从 Kafka 订阅 1kHz 阀动作 trace，用滑动窗侦测阀打开时间中位数从 8ms 跳到 14ms；本地脚本立即计算需补偿的 Purge 延长量，通过 ClawHub「ALD 配方微补偿」插件产生一份临时配方修正建议(将 Purge 延长 6ms)，同步推给制程工程师审核，并在群组里贴出膜厚预测曲线——获一键核准后由 Agent 经 SECS-II 下发给设备暂时撑住当前批，同时开出气阀更换工单。
**没有 Agent 的窘境**：膜厚偏移要等下线量测(Metrology)才发现，往往已是隔天，整批 25 片全报废；就算当下察觉，人工改配方、走变更核准流程要 40 分钟，腔体里的晶圆早就凉了。
**效益**：救回当前批 18 片晶圆(约 90 万美元)，膜厚偏移从「下线才知」变成「137 片时即补偿」，配方补偿决策时间 40 分钟 → 90 秒。

> 💡 君之一席话
> 「规格内，不代表安全；它只代表故障还没大声到让你听见——而毫秒，往往就是那道沉默的裂缝。」

> 🔍 高端点评──道路在哪里
> 这里龙虾做了一件危险而迷人的事：它对「正在跑的批」即时改配方。这指向 Agent 从「监看者」走向「在环(in-the-loop)补偿者」的道路。但动态改配方踩在制程变更管控(Change Control)的红在线——未来的工程问题是如何让 Agent 的每一次补偿都自带不可窜改的审计轨迹与自动回滚，让品质与良率部门能事后完整重建「为什么第 137 片之后配方变了」。

## 情境 73　离子布植(Implantation)射频(RF)功率突发性微幅跳变的即时防呆与熔断
**背景**：离子布植机(本场景为 RF-PVD/RF 电浆源)以 RF 电源(13.56 MHz)经自动匹配网络(Match Box，内含真空可变电容 VVC + 固定电感)把功率耦合进电浆源，将掺杂物打入晶圆。RF 正向(Pfwd)/反向(Pref)功率、VSWR(驻波比)、匹配电容位置(Cload/Ctune step)由设备每 10 ms 回报;为抓打火，另在定向耦合器后接宽带 RF 侦测器(包络输出，采样 ≥100 kHz)。
**问题**：布植途中 Pfwd 出现周期 0.5 秒(0.5 Hz)、幅度 ±2.1% 的规律性跳变，Pref 同步抖动、VSWR 由 1.05 阶跃到 1.25 又回落——这是 Match Box 真空可变电容打火(Arcing)的早期征兆。**打火的物理指纹**(用以对抗误判)：真空 VVC 在接口污染/真空度劣化时，电极间在 RF 峰值电压发生微放电——表现为 Pref 上的**次微秒级脉冲丛(burst)**、宽带 RF 包络出现 µs 级尖峰、VSWR 瞬时跃升并伴随匹配电容自动「追打火」反复微调(Ctune 抖动)。这与两种「正常/良性」状态必须分清：(a)正常匹配——VSWR 平稳 ≤1.1、Pref 低且无脉冲;(b)制程切换/调试阻尼——VSWR 缓慢单调收敛、无周期性、无 µs 脉冲丛，是匹配器在追阻抗而非放电。0.5 Hz 的规律性 + Pref 脉冲丛 + Ctune 反复追打火，三者同现才是打火，否则是阻抗漂移。剂量(Dose)随 Pfwd 起伏而微幅波动。
**问题的时间结构(决策关键)**：早期打火并非瞬间焚毁——从「微放电起始」到「VVC 接口碳化/电弧自持→匹配网络烧毁」典型有约 20–40 秒的劣化窗(放电能量逐丛累积、电极逐步碳化)。因此防呆不必在第一个丛就硬停，而要在窗内做**安全的停机点击择**。
**需要的技能**：RF 电浆匹配原理、VSWR/Pref 打火频谱与脉冲特征辨识、正常 vs 调试阻尼 vs 打火三态区分、剂量均匀性、停机延时决策与晶圆不可逆性评估。
**开源工具**：Node-RED(规则熔断流)、TimescaleDB、PyWavelets(小波侦测周期跳变)、SciPy(包络/脉冲丛侦测)、MQTT。
**用到的 Agent 特性**：龙虾子 Agent 对 Pfwd 跑小波变换锁定 0.5 Hz 规律跳变，同时对 Pref 宽带包络做脉冲丛侦测(µs 尖峰计数)、关联 VSWR 跃升与 Ctune 追打火，三特征交叉确认为「打火早期」而非阻抗漂移——0.4 秒内判定。**关键在停机延时决策而非无脑硬停**：Agent 依「劣化窗剩余裕度 vs 晶圆不可逆度」做决策——离子布植的剂量是累积积分量，**布植中途硬停的晶圆 Vt 必废(剂量打到一半无法补)**;而打火尚有 ~20–40 秒窗、且当前单丛能量低于 VVC 碳化阈值时，更优策略是**让当前晶圆跑完(只剩数秒)再于 wafer-to-wafer 间隙停机**，既不牺牲这片、又赶在烧毁前换修。决策分级：(i)若 VSWR 冲过硬保护线(如 >2.0)或脉冲丛能量陡升逼近碳化阈值→无安全裕度，立即经 SECS-II/GEM Interlock 硬停并标记当前片 Rework;(ii)若仍在裕度内且当前片 <10 秒结束→下「next-wafer HOLD」,放当前片跑完、下片不放、进间隙即停。再通过 Multi-Channel Gateway 把 Pref 脉冲丛波形、VSWR 轨迹、判定依据与建议检查的 VVC 编号推给布植区工程师与原厂 FSE。
**没有 Agent 的窘境**：±2.1% 跳变在面板看不见，工程师通常等匹配网络真烧了、机台 Alarm Down 才到场，赔上晶圆 + 一颗烧焦电容 + 4 小时换修;反过来，若有人警觉却不懂打火的时间窗，可能在第一个丛就硬停，反而把一片本可跑完的好晶圆判成 Rework——过度反应与反应不足都是错。
**效益**：打火从「烧毁才知」变成「劣化窗内择点熔断」;三态区分避免把调试阻尼误判成打火;停机延时决策在「保机台」与「保当前晶圆」间取最优，避免无谓 Rework;防呆触发→通报全程 < 2 秒，避免匹配网络烧损(换修 4 小时 + 备件约 1.5 万美元)。

> 💡 君之一席话
> 「最高明的维护不是坏了才停，也不是一抖就停——是看懂它还剩几秒可烧，把暂停键按在不牺牲这片晶圆、又赶在烧毁之前的那个缝隙里。」

> 🔍 高端点评──道路在哪里
> 这个场景的灵魂不只是「先熔断后通报」，而是「**懂得不要在第一秒硬停**」——把打火的劣化时间窗、与剂量这种不可逆累积量绑在一起做停机点击择，才是能抵御质询的工程判断。它把龙虾推上最敏感的道路：拥有 Interlock 运行权。一个能停机的 Agent 也能误停机，而误停一台满载布植机损失不亚于真故障;反过来，停太早牺牲好晶圆同样是损失。未来内核是分级授信 + 安全窗推理：哪些判定可直接硬停、哪些走 next-wafer HOLD、哪些必须人类二次确认，这条线决定无人化工厂能放手到哪一步。

## 情境 74　扩散炉管热电偶温度微幅震荡引发的批量晶圆报废阻击
**背景**：垂直扩散炉(Vertical Furnace)单批可装载 150 片晶圆，由五区热电偶(Thermocouple)构成 PID 闭环控温，温度曲线(Profile)以秒级记录，氧化/退火制程对温度极度敏感。
**问题**：炉管中央区热电偶在恒温段出现周期约 8 秒、幅度 ±0.4°C 的微幅震荡——这在面板上只是一条几乎平的线，但对成长中的闸极氧化层(Gate Oxide)是致命的厚度涟漪。根因是该支热电偶老化导致接点热电势漂移，PID 为了追随假信号反而把真实炉温越控越抖。150 片晶圆正在炉内爬升至制程温度，一旦进入恒温段，整批氧化层均匀度全毁，报废金额逾 600 万美元。
**需要的技能**：扩散炉 PID 控温原理、热电偶老化与冷接点补偿诊断、炉温 Profile 频谱分析、批量风险评估。
**开源工具**：Apache Spark Streaming、scipy(FFT 频谱)、Redis(即时状态)、Grafana。
**用到的 Agent 特性**：龙虾子 Agent 对五区温度做即时 FFT，发现中央区独有 0.125Hz 震荡而其余四区干净，交叉比对后判定「非制程扰动，而是该支热电偶信号源劣化」。在恒温段到达前，Agent 经 ClawHub「炉管批量风险决策」插件评估：当前在升温段、尚未定型，仍有救援窗。它通过 Multi-Channel Gateway 同步通报炉管工程师并建议「将控温主导权切换至备援热电偶区、暂缓进入恒温段」，附上五区频谱对比图，让工程师 90 秒内决策。
**没有 Agent 的窘境**：±0.4°C 的震荡没有任何告警会响，工程师通常在下线椭偏仪(Ellipsometer)量到氧化层厚度涟漪时才惊觉，那时 150 片早已是废片；事后追热电偶老化还要拆炉管调试一整天。
**效益**：批量报废从「下线才知」变成「恒温段前 90 秒阻击」，单次救回 150 片约 600 万美元，热电偶老化从盲区变成可频谱定位的可诊断项。

> 💡 君之一席话
> 「一条看似笔直的恒温线，藏着 0.4 度的心跳——你以为它在稳定，其实它在求救。」

> 🔍 高端点评──道路在哪里
> 这个案例最妙的是龙虾学会了区分「制程在抖」与「传感器在骗」——它指向 Agent 必须创建对「数据本身可信度」的判断力，也就是传感器自诊断(Sensor Self-Validation)。未来无人炉管的关键不是控温多准，而是当 PID 被一支说谎的热电偶带歪时，谁来吹哨。这条道路的尽头，是 Agent 不只监看制程，还要监看「监看制程的仪器」，形成一层元监控(meta-monitoring)。

## 情境 75　化学气相沉积(CVD)制程设备微幅振动异常的预测维护
**背景**：CVD 设备的干式真空泵(Dry Pump)与涡轮分子泵(Turbo Pump)长期高速运转，插件三轴 MEMS 振动传感器以 20kHz 采样，是腔体真空与粉尘控制的命脉。
**问题**：某腔体干式泵的振动 RMS 整体仍正常，但频谱在 287Hz 处冒出一个原本不存在的小峰，且每天长高 4%——这是泵浦轴承滚珠剥离(Spalling)的特征频率。若放任 11 天，轴承将抱死，泵浦真空骤失，CVD 腔体瞬间粉尘污染并回火(Backstreaming)，腔内 12 片晶圆全毁，泵浦更换 + 腔体清洗(Wet Clean)停机 8 小时。
**需要的技能**：滚动轴承故障特征频率计算、振动频谱与包络分析、真空泵失效模式、设备劣化趋势外推。
**开源工具**：librosa(包络解调)、numpy/scipy、Prophet(劣化趋势预测)、Apache Superset。
**用到的 Agent 特性**：龙虾子 Agent 对振动信号做包络解调(Envelope Detection)，在 287Hz 锁定轴承外圈故障频率(BPFO)的谐波族，再用 Prophet 外推峰值成长曲线，算出「11 天后越过抱死阈值」。本地脚本自动产生一份 PdM 报告(含频谱、谐波标注、剩余寿命信赖区间)，通过 Multi-Channel Gateway 推给设备可靠度工程师与备件仓管——并体贴地建议「第 7 天的计划保养窗一并更换，避免额外停机」，同时自动在备件系统查找该型号轴承库存与前置期。
**没有 Agent 的窘境**：人工点检振动多半看 RMS 总值，小峰被淹没在整体能量里完全看不出来；等到泵浦抱死、真空崩溃报警，已是污染腔体 + 整批晶圆陪葬 + 8 小时抢修，还可能因备件无库存而延长停机。
**效益**：轴承失效从「抱死才知」变成「11 天前频谱预警」，并对齐计划保养窗实现「零额外停机」更换，单次避免约 80 万美元晶圆 + 泵浦损失，PdM 报告产出 0 人工。

> 💡 君之一席话
> 「总振动值告诉你机器还活着，频谱里那根偷偷长高的小峰，才告诉你它正在死去。」

> 🔍 高端点评──道路在哪里
> 从 RMS 到包络频谱，龙虾在这里展示了「把振动翻译成倒数计时」的能力，而它真正的延伸道路是「对齐保养窗的时机优化」——预测坏掉只是第一步，把更换动作塞进既有的计划停机而不添加任何 downtime，才是省钱的本事。落地挑战在于跨系统协调：剩余寿命模型、备件库存与前置期、保养调度三者必须被同一个 Agent 拉到一张桌上谈判，这要求龙虾从单点诊断走向供应链与调度的多目标调度。

## 情境 76　晶圆搬运天车(OHT)伺服皮带张力衰退与轨道接缝卡顿的预测停靠
**背景**：自动化物料搬运系统(AMHS)的高架天车(OHT, Overhead Hoist Transport)在天花板轨道上以每秒数公尺穿梭，靠伺服马达 + 同步皮带升降晶圆盒(FOUP)，马达扭矩与编码器位置即时上报。
**问题**：某台 OHT 在通过 N-12 轨道接缝时，伺服扭矩反复出现 7% 的瞬时尖峰，且升降皮带在抓取 FOUP 时定位重复性从 ±0.1mm 退化到 ±0.4mm——皮带张力衰退叠加轨道接缝微错位。一旦升降定位偏差超过 0.5mm，FOUP 抓取就会打滑坠落，25 片晶圆连盒砸向洁净室地面，并造成轨道堵塞让整条 bay 的物流瘫痪。
**需要的技能**：OHT 伺服扭矩分析、同步皮带张力衰退诊断、轨道几何偏差定位、AMHS 物流调度。
**开源工具**：Eclipse Mosquitto(MQTT)、Pandas、PyOD(异常侦测)、Neo4j(轨道拓扑图)。
**用到的 Agent 特性**：龙虾子 Agent 把每台 OHT 的扭矩尖峰按轨道座标投影到 Neo4j 轨道拓扑图，发现「N-12 接缝」是多台 OHT 共同的扭矩热点(轨道问题)，而升降重复性退化只发生在这一台(皮带问题)，精准拆分根因。它通过 Multi-Channel Gateway 通报：对轨道发给设施(Facility)团队接缝校正工单；对该台 OHT 建议「派回维修侧线、预测性更换同步皮带」，并在 AMHS 调度层请求把该台暂时降载绕开高风险升降任务。
**没有 Agent 的窘境**：OHT 数以百计，人工根本分不清是「这台坏」还是「这段轨道烂」；通常要等 FOUP 真的坠落、晶圆砸地、bay 堵死，才在事故调查时翻 log 对座标，MTTR 以小时计且现场一片狼藉。
**效益**：FOUP 坠落从「事故后调查」变成「定位偏差退化期预测停靠」，避免一次坠盒(25 片约 125 万美元 + bay 物流瘫痪)，根因拆分(轨道 vs 皮带)从数小时人工比对 → 即时自动归因。

> 💡 君之一席话
> 「同一个扭矩尖峰，可能是轨道的错，也可能是皮带的错——分不清根因的维护，只是在猜谜。」

> 🔍 高端点评──道路在哪里
> 把故障投影到拓扑图、区分「设备问题」与「环境问题」，这指向龙虾未来的一条硬核道路：群体归因(Fleet-level Root Cause)。当你有上百台同型设备，个体告警毫无意义，唯有把全车队数据叠在同一张空间图上，共因才会浮现。工程难点在于把物理拓扑(轨道、bay、共用设施)建成 Agent 可推理的图模型，并在物流调度层拥有「降载绕行」的协调权——这已经不是维护，而是即时的车队指挥。

## 情境 77　光罩发送机械手臂真空吸盘(Vacuum Chuck)泄漏率渐增的微秒级防坠
**背景**：EUV 光罩(Reticle)价值动辄上千万美元，由专用机械手臂以真空吸盘吸附在 Pod 与曝光机间发送，吸附负压由压力传感器以 kHz 级监测。
**问题**：吸盘吸附 EUV 光罩时，达到稳定负压所需的「抽真空创建时间」在两周内从 45ms 缓慢拉长到 78ms，且稳态泄漏率(Leak Rate)上升——吸盘密封圈(O-ring)微裂老化。虽然每次仍能吸住，但安全余裕正在蒸发；某次若密封圈在搬运途中突破临界，光罩会在半空中脱吸坠落，一片价值连城的 EUV 光罩当场粉碎，并可能波及曝光机台。
**需要的技能**：真空吸附动力学、密封圈泄漏率趋势分析、EUV 光罩搬运安全规范、机械手臂时序诊断。
**开源工具**：InfluxDB、River(在线回归)、Grafana、Telegraf。
**用到的 Agent 特性**：龙虾子 Agent 在线追踪每次吸附的「真空创建时间」与稳态泄漏率，用 River 在线回归外推趋势，判定密封圈将在约 9 天后跌破安全余裕。考量标的是无价的 EUV 光罩，Agent 采最保守策略：本地脚本经 SECS 立即把该手臂的搬运速度上限降一档(牺牲节拍换安全余裕)，并通过 Multi-Channel Gateway 把泄漏率趋势、剩余安全天数、建议更换密封圈型号，最高优先级同步推给光罩区主管、设备工程师与 EHS 群组，要求 48 小时内排入 PM。
**没有 Agent 的窘境**：吸附「成功 vs 失败」是二元的，人工只看有没有吸住，根本不会去量「创建时间多了 33ms」这种余裕侵蚀；等到密封圈某天突然失效、光罩坠毁，已是天文数字损失加事故调查，整个光罩发送系统停摆。
**效益**：光罩坠毁风险从「失效当下才知」变成「9 天前余裕预警 + 即时降速保护」，单次避免潜在上千万美元光罩损失，吸附安全余裕从不可见指针变成可量化倒数。

> 💡 君之一席话
> 「它每一次都吸住了，所以你以为它没事——可余裕，正是用『每一次都成功』来掩盖它的崩溃倒数。」

> 🔍 高端点评──道路在哪里
> 这个场景把龙虾从「故障侦测」带到「余裕侵蚀(Margin Erosion)监控」的更高维度：不是等失败，而是量化「离失败还有多远」。它指向的道路是 Agent 主动以节拍换安全(降速保护)——这是一种会牺牲产能的决策。当标的物无比昂貵时，这种权衡很容易说服人；但当价值没那么极端时，「该不该为了 0.1% 的风险牺牲 5% 的产能」就成了无人化工厂最难的价值函数问题，这条线最终要交给可被治理的风险偏好设置。

## 情境 78　CMP 研磨头机械臂偏压马达电流不平衡导致研磨非均匀性的预测校正
**背景**：化学机械研磨(CMP)的研磨头(Polishing Head)由多区气囊施加偏压并由机械臂带动旋转/摆动，各区压力与驱动马达电流即时回报，直接决定晶圆表面平坦度(Planarity)。
**问题**：研磨头摆动臂的驱动电流在周期内出现左右不对称，外环区比内环区多耗 5.3% 电流——机械臂某侧轴承预载(Preload)松动，导致研磨压力分布偏斜。下线量到的晶圆边缘移除率(Removal Rate)开始系统性偏高，再不校正，晶圆边缘会过度研磨(Over-polish)露出下层金属，每片报废且趋势会吃掉整个 lot。
**需要的技能**：CMP 研磨机构力学、机械臂轴承预载诊断、移除率均匀性与电流关联分析、研磨配方补偿。
**开源工具**：Apache Kafka、scikit-learn、TimescaleDB、Metabase。
**用到的 Agent 特性**：龙虾子 Agent 将摆动臂左右驱动电流做对称性分析，锁定 5.3% 不平衡并关联下线移除率偏移，判定为轴承预载松动而非耗材(研磨垫)问题。本地脚本经 ClawHub「CMP 配方补偿」插件算出可暂时平衡边缘移除率的气囊压力微调量，推给制程工程师审核作为过渡;同时开出机械臂轴承预载重调工单，并通过 Multi-Channel Gateway 把电流对称性图与移除率趋势同步给 CMP 区工程师与设备团队，标注「补偿仅为止血，轴承须于 24 小时内复位」。
**没有 Agent 的窘境**：5.3% 电流不平衡藏在正常电流范围内无人察觉；工程师通常等下线发现边缘过研、甚至露金属层才回头查，那时整个 lot 的边缘晶粒(Die)良率已塌，根因卡在「是研磨垫寿命到还是机构问题」之间反复换耗材试错，浪费数班。
**效益**：边缘过研从「露金属才知」变成「移除率偏移初期预测校正」，避免整 lot 边缘良率损失(约 70 万美元)，并一刀切开「耗材 vs 机构」的归因迷雾，止血补偿决策 < 2 分钟。

> 💡 君之一席话
> 「同样的研磨偏差，换十次研磨垫都治不好——因为病根不在垫子上，在那颗松了的轴承里。」

> 🔍 高端点评──道路在哪里
> 龙虾在这里干的是「斩断错误试错路径」——它阻止工程师把机构问题误当耗材问题反复换垫。这指向一条极具价值的道路：Agent 作为归因仲裁者，把人类容易混淆的「耗材 vs 机构 vs 制程」三类根因用数据钉死。落地的关键是创建可信的因果关联库(电流特征 ↔ 机构故障模式 ↔ 下线量测),这需要长期累积标注数据；而「补偿止血 + 限时复位」的双轨动作，则要求 Agent 能追踪自己开出的暂时方案不被遗忘成永久妥协。

## 情境 79　多腔体集群设备(Cluster Tool)发送臂真空腔内定位偏移的累积误差熔断
**背景**：集群设备(Cluster Tool)以中央真空发送腔内的机械臂(Vacuum Robot)在多个制程腔体与 Load Lock 间调度晶圆，全程在真空与高温下进行，定位靠编码器 + 预教点(Teach Point)。
**问题**：真空发送臂在高温腔体热负载下，第 3 腔交接点的实际停靠位置相对教点以每百片 0.02mm 的速率累积偏移——热膨胀导致机构几何漂移。当累积偏移逼近 0.15mm，晶圆在交接时会与腔体陶瓷顶针(Lift Pin)边缘刮擦,轻则背面刮伤,重则晶圆在真空腔内碎裂,碎片污染全机台,需破真空(Vent)后人工清理,停机可达 12 小时。
**需要的技能**：真空机械臂热漂移补偿、预教点偏移趋势分析、晶圆交接几何安全、集群设备调度。
**开源工具**：Prometheus、Grafana、scipy、PostgreSQL。
**用到的 Agent 特性**：龙虾子 Agent 比对每次交接的编码器实际停靠位 vs 预教点，发现第 3 腔偏移随累积片数线性增长且与腔体温度正相关，判定为热漂移而非机构故障。Agent 设置动态安全阈值，在累积偏移达 0.12mm(留 0.03mm 缓冲)时本地脚本经 SECS 触发「软熔断」:暂停送往第 3 腔的派工并请求自动重教点(Auto Re-teach),同步通过 Multi-Channel Gateway 通报设备工程师偏移曲线与「已启动自动重教,请确认补偿结果"。
**没有 Agent 的窘境**：0.02mm/百片的漂移肉眼与面板皆不可见，工程师只能定期手动重教点,周期没抓准就会在某次交接刮伤甚至碎片;真空腔内碎片清理要破真空、拆腔、Wet Clean,整机台躺平半天到一天,并可能波及相邻腔体污染。
**效益**：真空腔碎片事故从「碎了才知」变成「0.12mm 软熔断 + 自动重教」，避免一次破真空清理(停机 12 小时 + 潜在污染)，热漂移从「定期盲目重教」变成「按累积偏移精准触发」，减少不必要重教中断。

> 💡 君之一席话
> 「每百片 0.02 毫米，小到没人会在意——但它有耐心，它会一直加，直到把晶圆送进顶针的刀口。」

> 🔍 高端点评──道路在哪里
> 累积误差是最阴险的故障，因为它没有单点异常、只有缓慢的漂移；龙虾在这里学会了「对缓变量设动态安全阈值并自动触发补偿(重教)」。这条道路通向 Agent 对机构的自我校正(Self-Calibration)能力——不只发现漂移，还能闭环修正。最大的工程信任边界是:让 Agent 自动重教真空臂的停靠座标,等于把机构的「真值」交给算法去重新定义,一旦自动重教本身出错,反而会把臂越教越歪,因此这类自校正必须配上独立的校正后验证关卡,不能让 Agent 既当运动员又当裁判。

## 情境 80　全厂机械手臂车队轴承健康的联邦化寿命建模与跨机台共因预警
**背景**：全厂数百支同型号晶圆发送机械手臂(EFEM/真空臂/OHT 升降)分散在数十台设备上，各自累积马达电流、振动、定位重复性数据,但隶属不同机台群、不同 vendor、数据散落各处。
**问题**：单台手臂的轴承劣化数据量太少,个别模型训练不出可靠的剩余寿命(RUL),导致预测不是太早(过度保养浪费)就是太晚(漏报故障)。同时,某批量同供应商的谐波减速机若有共通制造缺陷,个别机台各自为政完全看不出「这是一整批的系统性问题」,直到第 N 台接连故障才惊觉中了批量地雷。
**需要的技能**：剩余寿命(RUL)建模、联邦/跨机台数据治理、轴承批量共因分析、车队级可靠度工程。
**开源工具**：MLflow(模型管理)、Flower(联邦学习)、Apache Airflow(训练调度)、Evidently(模型漂移监控)。
**用到的 Agent 特性**：龙虾调度多个子 Agent 分驻各机台群在地萃取轴承特征(不外送原始 trace,仅交换模型梯度),由主 Agent 用 Flower 做联邦学习,把数百支手臂的劣化经验汇成一个共享的 RUL 模型,再用 MLflow 版本化、Evidently 监控模型漂移。当主 Agent 侦测到「2025-Q4 批号谐波减速机」的劣化斜率群体性偏陡,立即通过 Multi-Channel Gateway 向可靠度工程、采购与品保发出「批量共因预警」,附上受影响机台清单与建议的全厂主动更换批量。
**没有 Agent 的窘境**：各机台数据孤岛、各 vendor 各算各的,单台寿命模型样本稀少准度堪忧;批量缺陷只能靠故障数累积到「咦怎么又是这型减速机」才被人类事后拼凑,往往已坏了好几台、赔了好几批晶圆,召回式主动更换为时已晚。
**效益**：RUL 预测准度因联邦化样本暴增而大幅提升(过度保养与漏报双降),批量共因从「坏到第 N 台才发现」变成「劣化斜率群体偏陡时主动预警",把一场潜在的批量召回从灾难压成一次计划性主动更换。

> 💡 君之一席话
> 「一台手臂的故障是意外，一批手臂的故障是命运——而看穿命运的唯一方法，是把所有手臂的呻吟叠在同一张图上听。」

> 🔍 高端点评──道路在哪里
> 这是整章的收束,也是龙虾最远的一条道路:从单点 PdM 走向车队级联邦智能。它回答了前面所有场景隐含的问题——个别 Agent 看到的永远是局部,唯有把数百支手臂的劣化经验在不泄漏原始数据的前提下汇流,才能既训练出可靠的寿命模型,又抓出批量共因这种「个体永远看不见的系统性风险」。落地的工程深水区在于数据治理与信任:跨 vendor、跨机台群交换模型而不交换数据,需要严谨的联邦协定与模型漂移治理;而「全厂主动更换一整批减速机」这种动辄数百万的决策,则考验 Agent 的预警能否被采购与品保信服。无人化智能工厂的终局,不是更聪明的单台机器,而是一座会集体学习、彼此免疫的活的工厂。
