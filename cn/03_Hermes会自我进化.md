# 第3章　Hermes Agent：会自我进化的长期助理

## 一句 Slogan 撑起一整套架构

Hermes Agent 的官方标语只有一句话：

> **The agent that grows with you.（与你一同成长的代理。）**

别把它当行销词。这句话几乎定义了 Hermes 与龙虾最根本的分歧——龙虾赌「连接的广度」，Hermes 赌「成长的深度」。它由知名 AI 研究机构 **Nous Research** 推出（坊间因「爱马仕」的谐音暱称它为 🐴），主打的不是「能连几个平台」，而是「**用得越久，越懂你、越省你的钱**」。

## 自动写技能：把「解过的题」变成「会的题」

Hermes 最大的亮点，是一个听起来简单、做起来颠覆的机制：

**当它帮你完成一次复杂任务后，它会自动把这个解题步骤萃取、整理成一份「技能文档（Skill File）」。**

下次遇到类似任务，它直接调用这份文档，不需要你重新解释。

把这个机制和龙虾对照，差异是哲学级的：

| | 🦞 龙虾的技能 | 🐴 Hermes 的技能 |
|---|---|---|
| 来源 | **人工编写**，从 ClawHub 社群下载现成的 | **AI 自动写出**，根据你的真实工作流程 |
| 数量 | 13,000+ 把陌生人的瑞士刀 | 一把把「为你量身打造」的刀 |
| 成长 | 你装多少，它就会多少 | 你用越多，它自己长出越多 |

这就是「越用越省钱」的秘密——**重复的脉络，只需要被「学会」一次**。第一次你带着它走过一遍复杂流程，它把流程写成技能；往后同样的活，不再需要你逐句重讲。实测下来，这套机制可以省下高达 **90%** 的 Token 费用。龙虾的失忆让你每天重新付费，Hermes 的记忆让你的投资逐日累积。

## 子 Agent：一匹马，裂变成一支队伍

Hermes 的第二把利器，是「派生子 Agent」。

它可以帮你生出独立的「子 Agent（Sub-Agent）」，同时帮你跑不同的工作流。关键在于这些子 Agent 不是花瓶——

**每个子 Agent 拥有自己的对话上下文、独立的终端机，以及独立的 Python RPC 脚本。**

这意味着什么？意味着你可以让主 Agent 当「指挥官」，同时派出三匹子 Agent：一匹去跑测试、一匹去整理报表、一匹去盯着某个部署。彼此上下文隔离、互不污染，却又向同一个指挥中心汇报。一个人的工作流，被摊平成一支并行的队伍。

> 💡 君之一席话
> **龙虾的成长靠「插件」，Hermes 的成长靠「分裂与沉淀」。**
> 一个是不断往身上挂别人写好的工具，广度暴涨但个体不变聪明；一个是把每次经验沉淀成自己的技能、再裂变出队伍去并行。前者像收集宝可梦，后者像养成一个会自己读书的学徒。**用得越久，差距越大。**

## 不挑食的胃口：地端与云端通吃

要破除一个常见误解：很多人以为「能跑本地模型」是龙虾的专利，其实不是。

Hermes Agent 和 OpenClaw 一样，都是 AI Agent 框架，**都可以搭配本地模型跑，也都支持云端 API**：

- **地端模型**：如 Gemma、Llama 3 等，数据不出本机，隐私自己掌握。
- **云端 API**：OpenAI、Claude、OpenRouter 等，要更强的脑袋随时切换。

所以选择的关键从来不是「能不能跑模型」——这题两边都满分。真正的分水岭只有一道：**跑完一次任务之后，它记不记得、会不会把这次经验变成下次的本事。**

## 着重沙盒与权限：安全是设计，不是补丁

还记得龙虾那个「ClawHub 可能藏毒」的隐忧吗？Hermes 在这一点上走了相反的路。

相较于龙虾曾爆出多个漏洞、社群插件有恶意代码风险，Hermes 的架构**相对安全，着重沙盒（Sandbox）与权限控制**。当技能是 AI 根据你的工作流自己写的、在受控的沙盒里跑的，那条「一万三千个陌生人的供应链」风险，自然就被收敛掉了。

这也是为什么，当「弃虾养马」从一句玩笑变成一股风潮时，背后其实是一个很理性的权衡：**用户要的，从来不是更多的爪子，而是一个记得住、学得会、又不会反咬你一口的长期伙伴。**
