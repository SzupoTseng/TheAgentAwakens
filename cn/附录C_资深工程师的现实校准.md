# 附录C　现实校准：一个资深工程师对「百景」的补课

> 前面三篇 300 个情境，是一张**「可能性的地图」**，不是一份**「保证书」**。
> 它们大多写在「快乐路径（Happy Path）」上：Agent 永远判断正确、动作永远成功、MTTR 永远从 30 分钟掉到 45 秒。真实世界不是这样。这份附录，是一个把 Agent 放进生产环境踩过坑的人，替你补上的那一课——**让你在被愿景说服之后，还能活着把它落地。**

## 一、先承认三件百景没明说的事

**1. 那些漂亮的数字，是理想值。** 「MTTR 30 分钟 → 45 秒」成立的前提是：Agent 第一次就判断正确、下游 API 没挂、权限刚好够、没有第二个故障同时发生。真实事故往往是**复合的**——Agent 在告警风暴里，跟人类一样会被假象误导。请把百景的效益数字读成「**上界**」，不是「**期望值**」。

**2. 自主行动的反面是自主闯祸。** 一个能「自动 cordon 节点、自动 drain、自动改路由、自动杀进程」的 Agent，等于一个**有生产环境写权限的自动化帐号**。它判断对，是英雄；判断错，它用机器的速度把错误放大。情境里每一个「龙虾果断运行」，背后都该有一句没写出来的「**如果它判断错了呢？**」。

**3. ClawHub 的 13,000 个技能，是 13,000 条供应链攻击面。** 广度的代价在第 2 章讲过，这里再强调一次：你**装进来的每一个社群技能，都是别人写的、会在你生产环境里跑的代码**。把插件当依赖管，不是当魔法用。

## 二、把「Agent 自主行动」安全落地的六条铁律

这六条，是我愿意让 Agent 碰生产环境的最低门槛。少一条，我就把它降级回「唯读」。

> 🔍 铁律一：行动权要分级，别一步到位
> 把 Agent 的权限想成一道**阶梯**，而不是一个开关：
> **L0 唯读观测 → L1 告警关联与根因建议 → L2 提出具体动作（人按按钮）→ L3 受限自主（白名单动作 + 限额）→ L4 自主闭环。**
> 百景里那些「一键切换」「点击确认」的按钮，正是 **L2**——这是最被低估、也最该长期停留的一级。多数团队**永远不需要爬到 L4**；能稳定运行在 L2/L3，就已经赢了。

> 🔍 铁律二：每个自主动作都要有爆炸半径（Blast Radius）上限
> Agent 要杀 Pod？一次最多杀几个、超过就停下问人。要改路由？只能在预先声明的网段内。要缩容？设地板值。**没有限额的自主权，不是自动化，是一把上了膛的枪。** 对应到工程上：dry-run 预演、速率限制、自动动作的熔断器（连续 N 次动作无效就冻结自己并升级给人）。

> 🔍 铁律三：所有写入动作必须幂等且可回滚
> Agent 在网络抖动下可能把同一个动作做两次；它也可能做错。所以它碰的每一个 write，都要满足两个条件：**幂等（Idempotent，做两次等于做一次）**与**可回滚（Reversible，能一键还原）**。改了路由要存旧权重，缩了容要记原值，删东西前先快照——百景里龙虾「顺手做的快照」，其实是不可省略的前置动作。

> 🔍 铁律四：不可变的审计轨迹，是信任的地基
> 每一个 Agent 动作都要留下五个 W：**Who（哪个 Agent 身分）、When、What（做了什么）、Why（依据哪条推论／哪个告警）、Evidence（当时的证据快照）**，写进不可窜改的日志。事后你要能回答稽核员一句话：「为什么凌晨三点是它把那个节点关了？」答不出来，你就不该给它那个权限。

> 🔍 铁律五：划出「永远要人签核」的红线
> 有些动作，无论 Agent 多有把握，都必须人类最终确认。我的红线清单：**删除数据、生产数据库 DDL、动到钱、动到实体机台（晶圆厂／实验室尤其）、跨越资安边界、不可逆的容量变更。** 角色②③ 的世界里，一个错误的自主动作报废的是数百万美元的晶圆——**物理世界没有 Ctrl+Z，红线就要划得更深。**

> 🔍 铁律六：别让 Agent 对「自信的错误推论」采取行动
> LLM 最危险的特质，是它会用**一样的口吻**讲出对的结论和错的结论。高后果动作之前，要有**第二来源确认**：交叉比对另一个指针、要求另一个独立 Agent 复核、或设一个「信心门槛」——拿不准就降级成「建议」交给人。情境 20 里 Agent 当「裁判」中止混沌实验，前提必须是它对「失控」的判定有独立、可验证的证据，而不只是一个 LLM 的直觉。

## 三、谁来看守看守者（Who Watches the Watcher）

一个常被忽略的真相：**你的维运 Agent，本身就是一个需要被维运的生产系统。**

- **它也会挂。** Agent 跑在哪？它的依赖（LLM API、矢量库、ClawHub）谁在监控？当它沉默时，你怎么知道是「天下太平」还是「它自己死了」？→ 给 Agent 自己配 Heartbeat 与死人开关（Dead Man's Switch）。
- **它的控制平面是通信软件。** 百景的力量来自 Slack／Telegram／LINE。但反过来说：**通信平台挂了，你的指挥中枢就瞎了。** 别把唯一的应急信道绑死在单一 SaaS 上。
- **它会烧钱。** 一个自主 Agent 在告警风暴下可能疯狂调用 LLM 做推论。没有 **token 预算熔断**，一次大事故的 AI 帐单可能比事故本身还贵。
- **它是高价值攻击目标。** 一个有生产环境写权限、又听通信软件指令的 Agent，是攻击者的梦幻入口。**对 Agent 的指令信道做身分验证与权限最小化**，跟保护任何特权帐号一样严肃。

## 四、一条务实的 90 天导入路线

不要从「自主闭环」开始。从「**唯读的可信度**」开始。

| 阶段 | 时程 | 目标 | 退场条件（达标才进下一阶） |
|------|------|------|--------------------------|
| **第一阶：唯读观测（L0–L1）** | 第 1–30 天 | Agent 只看、只关联、只在群组发「根因建议」。**一行生产变更都不准做。** | 连续两周，它的根因判断与事后复盘一致率 > 80% |
| **第二阶：人在回路（L2）** | 第 31–60 天 | Agent 备好动作 + 证据，**人按按钮**。累积「它建议、人核可」的样本。 | 人类核可率高、且零误导性建议造成的事故 |
| **第三阶：受限自主（L3）** | 第 61–90 天 | 只对**白名单、低风险、可回滚**的动作开放自主（如重启无状态 Pod、清日志、补缺省限额），全程审计＋限额＋熔断。 | 自主动作零意外副作用，审计可追溯 |
| **（多数团队到此为止）** | — | L2/L3 的混合体，已经能吃掉大部分重复劳动与秒级救援的价值。 | — |

## 五、反模式清单（看到请喊停）

- **「先上 L4，出事再说」**——你会用机器速度制造你还没准备好收拾的灾难。
- **把 ClawHub 技能当魔法装**——未审计的第三方代码直接给生产权限。
- **没有回滚就让 Agent 写入**——等于把不可逆操作交给一个会犯错的系统。
- **审计日志可被 Agent 自己改**——看守者不能自己擦掉自己的脚印。
- **用「Agent 说它修好了」当验收**——要看系统的真实状态，不是看它回报「Done」。（这条，对人类工程师也成立。）
- **把唯一应急信道绑死单一通信 SaaS**——控制平面需要备援。

## 六、那么，这本书到底在说什么

把六条铁律与一条路线读完，你会发现它们收敛到序言那句话：

**自动化的尽头，不是「没有人」，而是「人只需要做最后那个决定」。**

百景描绘的是 Agent 能把**侦测、关联、备选方案、证据整理、跨团队通报**这些又累又慢的环节压到秒级；而把**那个带着后果、需要担责的「决定」**，干干净净地交还给你。

> 🔍 最后一席话
> 真正资深的工程师，不会问「Agent 能不能取代我」，而会问「**我能不能设计一个让 Agent 安全地替我跑腿、却把方向盘留在我手上的系统**」。
> 龙虾也好、爱马仕也好、明年那第三只动物也好——框架会换，但这个问题不会过时。**先成为那个值得被 Agent 服务的工程师，再去养你的 Agent。** 这，才是这 300 个情境真正想带你去发现的那条路。
