# 第2章　龙虾 OpenClaw：广度优先的自动化先驱

## 一只有二十四只爪子的章鱼

要理解龙虾，先理解它想解决的那个古老痛点：**你的数字生活，被切成了几十座孤岛。**

你的客服在 LINE，你的团队在 Slack，你的家人在微信，你的社群在 Telegram，你的工单在某个网页后台。每一座岛都要你亲自划船过去。OpenClaw 的回答简单而粗暴——**那就造一个能同时靠岸所有岛的港口。**

这个港口，就是它的内核：一个强大的「控制平面（Control Plane）」，对外能同时串联高达 **24 种以上**的通信软件群组（Telegram、LINE、Slack、微信……），对内则接上一座庞大的社群技能库。龙虾于二〇二五年底推出后，正是靠这套「广度优先」的打法，在 GitHub 上以极快的速度爆红。

## ClawHub：一万三千把现成的瑞士刀

如果说多平台连接是龙虾的左手，那 **ClawHub** 就是它的右手。

ClawHub 是龙虾的社群技能市集。它的数字很惊人：社群提供了 **超过 13,000 个现成技能（Skills）**。要让龙虾会发邮件、会查天气、会操作某个 SaaS、会跑某段运维脚本？多半不用自己写——去 ClawHub 抓一个现成的装上就行。

这就是龙虾的设计哲学落到实处的样子：

- **技能靠人工编写**：每一个 Skill 都是社群里某个人，为了某个具体需求，亲手写出来、分享出来的。
- **拿来即用**：你不必懂它怎么实作，装上、串好，龙虾就多了一只爪子。

对「想快速串起各种网络服务」的人来说，一万三千把现成的瑞士刀摆在面前，这种爽快感是其他框架短期内难以拷贝的。

> 💡 君之一席话
> **龙虾的强大，是一种「生态的强大」，不是「个体的聪明」。**
> 它不靠自己想出怎么做，而靠社群早就有人替它想好了。这让它在「广度」上几乎无敌——但也埋下了它后来最大的隐忧：**当技能来自一万三千个陌生人，你怎么确定每一把刀，刀柄里没有藏毒？**

## 广度的代价：失忆、恶意插件、与频繁的崩溃

魔法的另一面，是帐单。把龙虾从「玩具」养成「日常工具」的人，普遍撞上三件事：

- **痛点一・失忆（Stateless）**：龙虾以单次会话为主。每一次对话，几乎都像重新认识你一次。昨天教过的偏好，今天得再教一遍。对天天用它的人，这直接翻译成两个字——**烧钱**：每次都要重新喂脉络，Token 费用居高不下。
- **痛点二・毒插件（ClawHub 风险）**：生态扩大的代价，是品质失控。社群插件里开始出现夹带恶意代码的 Skill。你以为装的是一把瑞士刀，装进来的可能是一只木马。
- **痛点三・频繁崩溃**：系统更新节奏快，常常一更新就把用户自己辛苦配好的环境搞挂，跑出严重 BUG。于是社群里流传着各种「容易忘记步骤、把自己搞挂、每次更新就出大 BUG」的窘况。

这三件事叠在一起，就是「龙虾卸载服务」会出现的原因，也是下一章主角登场的理由。

## 但别急着看扁它——广度，在某些战场上就是王道

说了这么多痛点，本书要在这里为龙虾做一个重要的辩护，而这个辩护，会贯穿整个第三篇：

**在某些场景里，「广度」与「连接」本身，就是最稀缺的能力。**

想像一场大规模的在线事故：告警同时炸在 Slack 的 SRE 频道、Telegram 的架构师群、微信的主管群。这时候，一个「记性好但只会待在一个房间」的助理，远不如一个「能同时站在所有房间、把混乱的多方战场瞬间梳理成一张图」的连接器。

龙虾的 **Multi-Channel Gateway（多平台同步）** 与 **ClawHub 现成插件生态**，正是为这种「需要大规模多方通信 + 现成工具快速串接」的混乱战场而生。在第三篇的多云网络、金丝雀发布、混沌工程、跨团队排障里，你会反复看到它把泥淖中的地雷一颗颗排掉。

所以这本书的立场是：**龙虾不是被淘汰，而是被放回了它最该待的位置——当一个无与伦比的「连接器」。** 至于那个「会记忆、会自学、会省钱」的位置，留给下一章的马。
