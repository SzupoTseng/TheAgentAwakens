# 第18章　制程腔体：蚀刻、沉积与 CMP 的防呆

## 情境 31　CMP 研磨液(Slurry)pH 值微幅飘移引发的晶圆过度抛光自愈
**背景**：化学机械研磨(CMP)机台依赖研磨液的纳米级磨粒与化学蚀刻协同作用，pH 值决定了磨粒的 Zeta 电位与悬浮稳定性。
**问题**：凌晨 03:17，中央供液系统(Blend & Supply)的一桶铜制程研磨液 pH 从 10.4 缓慢飘至 10.9，仅 0.5 之差，但磨除率(Removal Rate)瞬间暴增 18%，正在抛光的第 9 片 300mm 晶圆铜层被多磨掉 220Å，再抛 40 秒就会见底碟陷(Dishing)报废，整批 25 片价值 380 万美元在燃烧边缘。
**需要的技能**：CMP 制程化学与 endpoint 侦测、SECS/GEM 即时数据拦截、PID 回馈控制、统计制程管制(SPC)。
**开源工具**：`secsgem`(Python SECS/GEM 函数库)、`InfluxDB` + `Telegraf`(时序数据采集)、`Grafana`(即时看板)、`scikit-learn`(磨除率漂移回归)。
**用到的 Agent 特性**：龙虾 OpenClaw 通过 `secsgem` 订阅了供液站的 SV(Status Variable)串流，本地脚本每 200ms 比对 pH 与磨除率的耦合斜率。当斜率超出 SPC 上控制线，龙虾不等人类确认，先以子 Agent 下 PauseSubstrate 暂停当前 step，同时调用 ClawHub 上的「CMP-RR-Compensator」技能插件，动态缩短剩余抛光时间 11 秒以补偿超额磨除，并通过 Multi-Channel Gateway 同步把「已自愈，pH 飘移待处理」推到 LINE 群、Teams 与机台 MES 注记。
**没有 Agent 的窘境**：工程师被叫醒、开 VPN、登录 FDC 系统捞三十分钟前的趋势图、才发现是供液端 pH，这时整批早已碟陷报废，事后只能写 8D 报告。
**效益**：过抛拦截 MTTR 由人工约 28 分钟缩短至 9 秒；单批挽救 380 万美元，年化避免报废估 2,400 万美元。

> 💡 君之一席话
> 「研磨液不会大声喊救命，它只会用 0.5 的 pH 悄悄把你一整批的利润磨成泥浆。」

> 🔍 高端点评──道路在哪里
> 这个案例指向龙虾未来最关键的一条道路：从「监看 SV」走向「即时介入制程控制环路」。当 Agent 开始下 PauseSubstrate，它就跨过了读写权限的信任边界——一旦补偿算错，自愈反而变成自残。落地时真正的工程问题不是侦测，而是「谁为 Agent 的补偿参数背书」：未来必须有一层可审计的决策影子帐本(shadow ledger)，让每一次自动补偿都能被制程工程师事后重演与否决。

## 情境 32　CVD 制程气体流量计(MFC)突发性卡死的秒级安全排空
**背景**：化学气相沉积(CVD)腔体靠多路质量流量控制器(MFC)精准配比硅烷(SiH₄)、氨气与载气，任何一路失准都会破坏薄膜化学计量比。
**问题**：一台 PECVD 在沉积氮化硅时，硅烷那路 MFC 的设置值是 120 sccm，回授值却冻结在 118 sccm 不再变动——MFC 内部阀卡死。实际流量可能已飙到满开 200 sccm，腔内硅烷分压失控，距离可燃下限(LFL)只剩数十秒，一旦点火即是腔体爆裂。
**需要的技能**：气体输送系统(Gas Box)安全联锁、MFC 失效模式辨识、Interlock 逻辑、有毒/易燃气体紧急进程。
**开源工具**：`Node-RED`(联锁流程编排)、`Eclipse Mosquitto`(MQTT 消息汇流)、`Telegraf`(MFC 回授采集)、`OpenPLC`(安全 PLC 仿真与验证)。
**用到的 Agent 特性**：龙虾的本地脚本侦测到「setpoint 与 readback 连续 3 秒零变异但 step 仍在进行」这种 MFC 冻结指纹，立刻判定为卡死失效模式，通过 MQTT 触发 Gas Box 的紧急排空(Purge)联锁，切硅烷主阀、开氮气稀释、启动腔体抽真空，全程 4.2 秒。同时子 Agent 生成事件时间轴，Multi-Channel Gateway 把「CVD-07 MFC 卡死已安全排空、人员勿靠近」一键广播到工安群与设备群。
**没有 Agent 的窘境**：操作员要先怀疑薄膜厚度异常，再回头查 MFC，等他判读完，腔内早已超过爆炸下限——这是用人命在赌反应时间。
**效益**：危险排空反应从人工平均 90 秒以上压到 4.2 秒；杜绝一次潜在腔体爆裂工安事故，并避免机台 24 小时拆检停机。

> 💡 君之一席话
> 「一个冻住不动的数字，比一个乱跳的数字危险十倍——因为前者让你以为一切安好。」

> 🔍 高端点评──道路在哪里
> 这里龙虾走的是「Agent 作为软性安全联锁层」的道路。传统 Fab 的安全靠硬接线 PLC，反应快但逻辑死板；Agent 能辨识「冻结」这种硬联锁抓不到的软性失效。但这正是最危险的信任边界:安全相关决策若交给可能幻觉的 LLM，认证(SEMI S2/IEC 61508 SIL)要怎么通过?未来的道路必然是「Agent 提早预警、硬联锁最终兜底」的双层架构,而非让 Agent 直接触发安全动作——这条规模化之路绕不开功能安全认证这座大山。

## 情境 33　APC(先进设备控制)参数失控引发晶圆过度蚀刻的动态拦截
**背景**：先进设备控制(APC)以 Run-to-Run(R2R)回馈自动微调蚀刻时间,补偿腔体老化与消耗品漂移,让每片 CD(关键尺寸)落在目标。
**问题**：一颗 R2R 控制器因前一批量测机台回传了一笔离群值(outlier CD 低了 4nm),APC 误判蚀刻不足,把下一批的蚀刻时间从 47 秒一路加码到 53 秒。实际上量测根本是误报,这 6 秒的过蚀将把闸极线宽蚀穿,整批 50nm 结构直接断路。
**需要的技能**：APC/R2R 控制理论、量测离群侦测、EWMA 滤波、Exponentially Weighted Moving Average 调机逻辑。
**开源工具**：`pandas` + `scikit-learn`(离群侦测)、`PyOD`(异常检测函数库)、`secsgem`(拦截 recipe 下载)、`Grafana`(APC 趋势)。
**用到的 Agent 特性**：龙虾在 APC 把新 recipe 下载到蚀刻机之前的最后一哩拦截——它用 PyOD 对回授的 CD 量测做 isolation forest,发现该笔 CD 是孤立离群点(Mahalanobis 距离爆表),立即通过 ClawHub 的「R2R-Sanity-Gate」插件挡下这次调机,把蚀刻时间锁回上一个健康值 47 秒,并开子 Agent 去交叉比对量测机台的校正纪录。Multi-Channel Gateway 通报制程集成(PI)工程师:「APC 收到一笔疑似误报量测,已拦截过度加码,请查量测机。」
**没有 Agent 的窘境**：没人会盯着 APC 每一次的微调,大家信任这个黑盒子——直到下一站电性测试良率崩盘,才回头挖出是两天前一笔脏量测污染了控制器。
**效益**：过蚀批量拦截率近 100%;单批挽救加上避免 APC 控制器被脏数据持续污染,年化良率损失减少约 1.5%。

> 💡 君之一席话
> 「自动控制最大的盲点,是它从不怀疑喂给自己的数字——而怀疑,正是智能的起点。」

> 🔍 高端点评──道路在哪里
> APC 是 Fab 里最早的「自动化」,而龙虾在这里扮演的是「监督自动化的自动化」(meta-control)。这指向一条深刻的道路:当工厂里的自动控制器越来越多,谁来监督控制器?Agent 正在成为那一层 sanity gate。但这带来协调难题——多个 Agent 与多个 APC 控制器互相拦截、互相锁值,可能产生振荡甚至死锁。未来规模化的内核工程问题,是创建 Agent 之间的「介入仲裁协定」,确保 meta-control 不会演变成多智能体的集体瘫痪。

## 情境 34　干式清洗电浆发生器反射功率(Reflected Power)异常的就地防护
**背景**：蚀刻与沉积前的干式电浆清洗,靠 RF 发生器与匹配网络(Matching Network)把功率耦合进电浆。反射功率代表阻抗失配,过高即烧匹配器或熄火。
**问题**：一台 ICP 蚀刻机在 cleaning step,前传功率 1500W,反射功率本该 <30W,却在 4 秒内从 25W 冲到 340W——匹配网络的可变电容步进马达卡滞,阻抗匹配失败。再几秒,反射的驻波会把匹配箱里的真空电容烧穿,维修需停机 18 小时并换 12 万美元的零件。
**需要的技能**：RF 电浆物理、阻抗匹配原理、驻波比(VSWR)诊断、RF 发生器联锁。
**开源工具**：`InfluxDB`(高频 RF 遥测)、`Node-RED`(就地联锁)、`Mosquitto`(MQTT)、`NumPy`(VSWR 即时计算)。
**用到的 Agent 特性**：龙虾以 10ms 分辨率监看前传/反射功率对,本地脚本即时算 VSWR,当反射功率斜率超过 60W/s 且 VSWR>2.5,判定为匹配失效而非制程波动,立刻下 RF Off 并让发生器进 standby,赶在电容烧穿前 0.8 秒切断功率。子 Agent 自动把匹配器电容位置、马达电流、step 时间打包成诊断快照。Multi-Channel Gateway 通知设备工程师:「ICP-03 匹配网络电容卡滞,已就地切 RF,建议排检步进马达。」
**没有 Agent 的窘境**：人靠耳朵听机台异音或事后看 alarm log,等发现时匹配箱已冒烟,12 万零件报销加 18 小时停机。
**效益**：RF 切断反应 MTTR 由人工数十秒降至 <1 秒;单次避免 12 万美元零件损失与 18 小时稼动损失。

> 💡 君之一席话
> 「电浆熄灭只是制程中断,匹配箱烧穿才是钱包真正的灰飞烟灭——救机台要救在功率切断的那 0.8 秒。」

> 🔍 高端点评──道路在哪里
> 这个场景把龙虾推向「边缘即时防护」的道路——10ms 级的反应已经逼近云端 Agent 的延迟极限。它揭示了一个规模化现实:真正攸关设备安全的反应,不能绕一圈云端推论。龙虾的未来必然是「边缘轻量决策核 + 云端深度推理」的分层架构,把毫秒级的硬反应下沉到机台旁的工业电脑。落地的信任边界在于:边缘那颗精简 Agent 的决策逻辑如何与云端大脑保持一致而不漂移,这是分布式 Agent 一致性的经典难题在 Fab 的重演。

## 情境 35　CMP 研磨垫(Pad Wear)微幅磨损引发的假性过抛防御
**背景**：CMP 的研磨垫随抛光次数磨损,垫面沟槽变浅、表面变硬,改变晶圆与垫的接触力学,使同一 recipe 下的磨除率随垫寿命缓慢漂移。
**问题**：一片研磨垫已用到第 1,180 片,垫厚从 2.0mm 磨到 1.62mm,endpoint 系统的马达电流信号因垫变硬而提早触发,系统「以为」到了终点而停止——这是假性 endpoint。实际上钨层还剩 300Å 没磨平,留下残留金属(residue),下一站短路,但若机台据此误判去延长抛光,又会反过来过抛邻近区域。一垫两难。
**需要的技能**：CMP endpoint 信号处理、研磨垫寿命建模、马达电流/摩擦力信号分析、消耗品寿命管理(Consumable Management)。
**开源工具**：`scipy.signal`(endpoint 信号去趋势)、`scikit-learn`(垫寿命回归补偿)、`secsgem`(endpoint 事件拦截)、`Grafana`(垫寿命看板)。
**用到的 Agent 特性**：龙虾学了过去 1,180 片的「endpoint 马达电流曲线 vs 垫寿命」关系,本地脚本对当前 endpoint 信号做垫磨损补偿(de-trend),识破这是「垫变硬造成的假性 endpoint」而非真到终点。它不盲目延长抛光,而是调用 ClawHub 的「Pad-Aware-Endpoint」插件,改用补偿后的真实终点判据再抛 8 秒清除残留,同时子 Agent 计算研磨垫已逼近寿命上限,提前下换垫工单。Multi-Channel Gateway 同步推:「CMP-02 侦测假性 endpoint(垫磨损致),已用补偿判据完成,并预约换垫。」
**没有 Agent 的窘境**：工程师通常等良率出问题或残留缺陷被扫描到,才回头怀疑研磨垫;在那之前已有数十片带着残留金属流到下一站。
**效益**：假性 endpoint 导致的残留缺陷批量归零;换垫由事后补救转为预测性更换,稼动率提升约 3%,残留报废年化省约 600 万美元。
> 💡 君之一席话
> 「机台说『我到终点了』,不代表晶圆到了终点——会老化的不只是研磨垫,还有你对传感器的盲目信任。」

> 🔍 高端点评──道路在哪里
> 这指向龙虾最有价值的一条道路:把「消耗品的隐性老化」变成可被 Agent 补偿的显性模型。Fab 里几乎每个传感判据都会随消耗品漂移,这是良率工程的暗物质。Agent 一旦能为每一种消耗品创建「老化—信号」的补偿模型,等于给整厂的传感器都装上自动校正。但规模化的工程问题随之而来:这些补偿模型会 model drift,且每台机、每批垫都略有不同,未来必须有一套 Agent 自我重训与版本管理机制,否则「会补偿的 Agent」终将补偿出新的系统性偏差。

## 情境 36　多腔体沉积厚度量测机(Metrology)校正漂移引发的链式误调拦截
**背景**：沉积后的薄膜厚度由椭偏仪(Ellipsometer)量测,量测值回馈给 APC 调整下一批沉积时间,形成闭环。量测机本身的校正漂移会污染整条控制链。
**问题**：一台椭偏仪的参考光源缓慢老化,所有厚度量测系统性偏高 1.8%。APC 信以为真,连续三批把沉积时间缩短,实际膜厚已比目标薄 32Å,接近介电崩溃风险窗,却没有任何单一 alarm 触发——因为每一步都「在规格内」,是慢性中毒。
**需要的技能**：量测系统分析(MSA/Gauge R&R)、椭偏仪原理、跨机台量测一致性(matching)、慢漂移侦测。
**开源工具**：`statsmodels`(趋势显著性检定)、`PyOD`(系统性偏移侦测)、`InfluxDB`(跨机台量测历史)、`secsgem`(量测数据拦截)。
**用到的 Agent 特性**：龙虾同时订阅三台椭偏仪对同一监控片(monitor wafer)的量测,本地脚本用 statsmodels 做跨机台一致性比对,发现第 2 台对标准片的读值出现单调上漂(Mann-Kendall trend 显著),判定是该机校正漂移而非真膜厚变化。它通过 ClawHub「Metro-Matching-Guard」插件把这台机的量测暂时降权,冻结受污染的 APC 回馈,并开子 Agent 排该机重新校正(re-cal)。Multi-Channel Gateway 通报:「Ellip-02 校正漂移 1.8%,已隔离其 APC 回馈,请运行光源更换与 re-cal。」
**没有 Agent 的窘境**：量测机的慢漂移是 Fab 最难抓的鬼故事,通常要等到客户端可靠度失效或月度 MSA 才发现,期间整条沉积线已被悄悄带偏好几周。
**效益**：量测漂移污染拦截从「数周」缩短到「同日」;避免一条沉积线数周的系统性膜厚偏移,年化挽救良率损失约 2%。
> 💡 君之一席话
> 「最可怕的故障从不触发警报——它让每一步都在规格内,却让终点偏离真理。」

> 🔍 高端点评──道路在哪里
> 这个案例把龙虾带上「测量信任的守门人」道路。Fab 的闭环控制有个哲学前提:量测是可信的。当这个前提被慢漂移侵蚀,所有自动化都成了精准的犯错。Agent 用跨机台冗余比对来重建「真理」,本质上是在做分布式真值共识。落地的工程问题是:需要足够的量测冗余(多机/监控片)才能让 Agent 投票出真值,而冗余是成本。未来的道路在于用更聪明的虚拟量测(Virtual Metrology)补足物理冗余的不足,让 Agent 不必靠多买量测机就能守住测量信任——这正是 AI 与 Fab 最性感的交会点。

## 情境 37　ALD 前驱物钢瓶(Bubbler)液位耗尽引发的沉积断层自动换瓶
**背景**：原子层沉积(ALD)用钢瓶(Bubbler)汽化液态前驱物,靠载气带出蒸气脉冲。前驱物将尽时蒸气压不足,沉积会出现原子层级的厚度断层。
**问题**：一个 HfCl₄ 前驱物钢瓶液位将尽,蒸气输出量在连续晶圆间掉了 12%,正在跑的是 28 层 high-k 闸极介电,任何一层欠量都让 EOT(等效氧化层厚度)失准,整批高端逻辑晶圆电性报废。传统液位侦测要等「空瓶 alarm」才换,但那时已经来不及。
**需要的技能**：ALD 自我限制反应机制、前驱物输送(Precursor Delivery)、蒸气压监测、钢瓶自动切换(Auto-switchover)。
**开源工具**：`Telegraf`(钢瓶温度/压力采集)、`Node-RED`(切换流程编排)、`Mosquitto`(MQTT)、`scikit-learn`(蒸气输出衰减预测)。
**用到的 Agent 特性**：龙虾不依赖空瓶 alarm,而是学蒸气脉冲下降缘的斜率——本地脚本侦测到连续脉冲的饱和峰值出现衰减趋势,提前约 40 片预测前驱物将不足。它在批量间的安全间隙触发 Node-RED 自动切换到备援钢瓶,完成预热与管路 purge,确保下一片无缝衔接,全程不中断 lot。子 Agent 自动产生空瓶更换工单。Multi-Channel Gateway 通报:「ALD-05 主钢瓶蒸气衰减,已预测性切备援瓶,lot 无中断,请更换空瓶。」
**没有 Agent 的窘境**：等空瓶 alarm 响,当前晶圆的某几层已欠量,轻则该片报废,重则因切换时的压力扰动毁掉整个 lot。
**效益**：前驱物耗尽导致的沉积断层批量归零;换瓶从「中断式被动」变「无缝预测性」,稼动率提升约 2%,挽救高端晶圆报废年化估 800 万美元。
> 💡 君之一席话
> 「在原子层的世界里,你不能等瓶子喊空——你得在它还剩最后一口气时就完成交棒。」

> 🔍 高端点评──道路在哪里
> ALD 换瓶把龙虾推向「预测性物料衔接」的道路——从监控状态,进化到预测耗尽并主动编排交接。这指向 Agent 在 Fab 物料供应链的更大野心:不只换一个钢瓶,而是统筹全厂数百个消耗品的寿命与库存。但规模化的真正瓶颈是「无缝」二字背后的时序协调:换瓶必须卡在批量间隙,多机台同时告急时谁先换、备援瓶是否够用,这变成一个即时资源调度问题。未来龙虾的道路是与 Fab 调度系统深度耦合,让物料 Agent 与生产 Agent 对话——而跨系统 Agent 协作的权责边界,将是下一个十年的工程主战场。

## 情境 38　深沟槽蚀刻负载效应(Loading Effect)导致蚀刻速率漂移的批内补偿
**背景**：电浆蚀刻存在负载效应——当晶圆上待蚀刻面积(开口率)不同,消耗的反应物不同,蚀刻速率随之变化,微负载(microloading)更会在芯片内造成深度不均。
**问题**：一个 lot 混跑了两种开口率差异达 35% 的产品,蚀刻机用同一 recipe,高开口率那几片因反应物被大量消耗,深沟槽(DTI)蚀刻深度浅了 8%,深度从目标 6μm 只到 5.5μm,沟槽电容失准,影像传感器暗电流超标报废。
**需要的技能**：电浆蚀刻负载效应建模、开口率(pattern density)解析、批内(within-lot)补偿、反应物消耗动力学。
**开源工具**：`NumPy`/`pandas`(开口率与速率建模)、`scikit-learn`(负载补偿回归)、`secsgem`(per-wafer recipe 微调)、`Grafana`(蚀刻深度分布)。
**用到的 Agent 特性**：龙虾从 MES 读取每片晶圆的产品别与开口率,本地脚本用历史建好的「开口率—蚀刻速率」负载模型,为 lot 内每一片动态计算补偿后的蚀刻时间(高开口率片补时间),通过 secsgem 在每片进腔前微调 recipe 的 etch step。它把批内补偿变成逐片(per-wafer)自适应,而非整批一刀切。子 Agent 记录每片补偿量供事后验证。Multi-Channel Gateway 通报 PI 工程师:「混批侦测到 35% 开口率差,已启动逐片负载补偿,深度均匀性维持 ±2%。」
**没有 Agent 的窘境**：工程师为了避免负载效应,通常禁止混批或保守设 recipe,牺牲弹性与产能;若混批失误,整批深度不均要到电性测试才暴露。
**效益**：混批深度不均报废归零;允许安全混批使机台稼动弹性提升约 15%,并挽救影像传感器批量报废。
> 💡 君之一席话
> 「同一道 recipe 喂给开口率不同的晶圆,就像同一个火候煎厚薄不一的牛排——均匀的秘密,在于懂得为每一片微调时间。」

> 🔍 高端点评──道路在哪里
> 这个场景揭示龙虾走向「逐片自适应制程(per-wafer adaptive process)」的道路——把 Fab 从「批量思维」带向「个体化处理」。这是 Advanced Process Control 的圣杯:每片晶圆都用为它量身计算的参数。Agent 在这里是逐片决策的运行引擎。但落地的工程问题尖锐:逐片改 recipe 意味着每片都是「不同的制程条件」,这对制程资格认证(qualification)与可追溯性是巨大挑战——监管与品质体系创建在「制程一致」的假设上。龙虾的未来道路,是让「自适应」与「可审计、可重现」并存,这需要一套全新的逐片制程履历标准。

## 情境 39　CMP 抛光头薄膜压力(Membrane Pressure)失衡引发的晶圆内均匀度抢救
**背景**：CMP 抛光头用多区(multi-zone)气压薄膜把晶圆压向研磨垫,各区独立压力控制晶圆内(within-wafer)的磨除均匀度,边缘与中心分区施压。
**问题**：一台 CMP 抛光头的边缘区(zone 5)气路出现微泄漏,压力从设置 3.5 psi 慢慢掉到 3.1 psi,晶圆边缘磨除不足,边缘 5mm 环带残留铜厚多了 180Å,中心却正常——晶圆内均匀度(WIWNU)从 4% 恶化到 11%,边缘良率崩盘,但整片平均厚度看起来「正常」。
**需要的技能**：CMP 多区压力控制、晶圆内均匀度(WIWNU)分析、气路泄漏诊断、抛光头机构知识。
**开源工具**：`InfluxDB`(多区压力遥测)、`scipy`(均匀度径向分析)、`Node-RED`(压力补偿联锁)、`Grafana`(WIWNU 趋势)。
**用到的 Agent 特性**：龙虾监看抛光头五个区的压力 setpoint 与 readback,本地脚本发现 zone 5 出现持续性的负偏差(readback 系统性低于 setpoint),且该偏差与下游量测的边缘残留升高高度相关,判定是边缘区气路泄漏。它调用 ClawHub「CMP-Zone-Balancer」插件,在泄漏被修复前先把 zone 5 的 setpoint 加压补偿 0.4 psi 以暂时拉回边缘均匀度,同时子 Agent 开抛光头维修工单并标记该头限用。Multi-Channel Gateway 通报:「CMP-04 zone 5 气路泄漏致边缘 WIWNU 恶化,已加压补偿并排修抛光头。」
**没有 Agent 的窘境**：平均厚度正常会骗过粗略监控,工程师往往等到边缘良率地图(edge yield map)变红才警觉,期间整批晶圆的边缘晶粒已报废。
**效益**：WIWNU 从 11% 即时拉回 5% 以内;抢救边缘良率,避免抛光头泄漏期间整批边缘晶粒报废,单批挽救约 200 万美元。
> 💡 君之一席话
> 「看平均值会让你睡得安稳,看分布才会让你睡得安全——边缘崩坏时,平均数是最温柔的谎言。」

> 🔍 高端点评──道路在哪里
> 这个案例把龙虾推向「空间分布感知(spatial-aware)」的道路——从监看纯量(平均厚度)进化到理解径向/区域的分布形貌。Fab 的良率杀手大多藏在空间分布里,而非平均值。Agent 一旦能把压力分区、量测地图、缺陷座标在同一空间座标系里关联推理,就能找出人类肉眼难察的局部根因。规模化的工程问题在于:这需要把异质数据(压力时序、晶圆地图、缺陷影像)空间对齐与融合,是个数据工程的硬骨头。未来龙虾的道路,是成为跨制程的「晶圆空间数字分身」推理者——而这条路的信任边界,在于它的补偿动作会改变物理机构受力,必须有机构安全上限兜底。

## 情境 40　跨腔体匹配(Chamber Matching)漂移引发的多机台沉积一致性自动再平衡
**背景**：同型号的多座沉积腔体应视为「一致」,让晶圆在任一腔处理结果相同(chamber matching)。但腔体各自老化,壁面沉积、零件寿命不同,匹配会随时间漂移。
**问题**：一个 PVD 机群有 4 座腔体,腔体 C 因靶材已用到寿命后段,沉积速率比其余三座慢了 6%,调度系统却仍把晶圆平均分配进去。流经腔体 C 的晶圆膜厚系统性偏薄,而 SPC 因混了四腔的数据被「平均」掉,单腔趋势被稀释,问题潜伏两周才浮现,期间数千片受影响。
**需要的技能**：腔体匹配(Chamber Matching)、靶材寿命管理、依腔分群 SPC(per-chamber SPC)、虚拟量测。
**开源工具**：`statsmodels`(per-chamber 趋势分解)、`PyOD`(腔间离群)、`InfluxDB`(分腔历史)、`secsgem`(per-chamber recipe offset 下载)。
**用到的 Agent 特性**：龙虾坚持把数据依腔体拆开分析,本地脚本对四座腔做 per-chamber SPC,识破腔体 C 的沉积速率单调下漂(被合并 SPC 掩盖的信号),判定为靶材寿命末期匹配漂移。它调用 ClawHub「Chamber-Rematch」插件,为腔体 C 动态下一个 +6% 的时间 offset 把它拉回与其他三腔一致,同时子 Agent 依靶材剩余寿命排换靶工单并建议调度暂时降载腔 C。Multi-Channel Gateway 通报设备与 PI:「PVD 腔体 C 匹配漂移 6%(靶材末期),已下 recipe offset 再平衡,并排换靶。」
**没有 Agent 的窘境**：合并 SPC 是 Fab 经典盲区,单腔慢漂被三座好腔稀释,等良率工程师手动拆腔分析,已是两周后、数千片之后。
**效益**：腔体匹配漂移侦测从「两周」缩到「当班」;避免单腔系统性偏移污染数千片,并把换靶转为寿命驱动的计划性维护,年化挽救良率损失约 2.5%。
> 💡 君之一席话
> 「把四座腔的数据搅成一锅平均,就是把一座坏腔的求救声,溶解在三座好腔的合唱里。」

> 🔍 高端点评──道路在哪里
> 跨腔匹配把龙虾带上「群体一致性治理(fleet-level consistency)」的最高境界——不再看单机,而是统筹整个机群的趋同。这是无人化智能工厂的内核命题:让数十座腔体像一座腔体般行为一致。Agent 在这里是机群的指挥家,持续微调每座腔的 offset 维持趋同。但这条道路的工程深渊在于:当 Agent 为了「匹配」而不断给各腔加 offset,它可能掩盖了某座腔真正该被汰换的硬件劣化——再平衡与该修则修之间的界线在哪?未来龙虾的道路,是同时持有「短期再平衡」与「长期健康度」两本帐,知道何时该补偿、何时该喊停让人类换硬件。能分辨「修补」与「治本」,才是 Agent 从运维工具走向工程伙伴的成年礼。
