# 第3章　Hermes Agent：自己自身を進化させる長期アシスタント

## たった一行のスローガンが、アーキテクチャ全体を支える

Hermes Agent の公式スローガンは、たった一文だけだ。

> **The agent that grows with you.（あなたとともに成長するエージェント。）**

これをただのマーケティング文句だと思ってはいけない。この一文こそが、Hermes とロブスターの最も根本的な分岐点をほぼ定義している——ロブスターは「接続の広さ」に賭け、Hermes は「成長の深さ」に賭けたのだ。Hermes は著名な AI 研究機関 **Nous Research** が世に送り出したもので（巷では「愛馬仕（エルメス）」の語呂合わせから 🐴 という愛称で呼ばれている）、その売りは「いくつのプラットフォームとつなげるか」ではなく、「**使えば使うほど、あなたを理解し、あなたのコストを節約する**」という点にある。

## 自動でスキルを書く：「解いた問題」を「解ける問題」に変える

Hermes の最大の見どころは、聞けば単純だが、やっていることは破壊的な一つのメカニズムだ。

**複雑なタスクを一度こなすと、Hermes はその解法の手順を自動的に抽出・整理し、一つの「スキルファイル（Skill File）」にまとめる。**

次に似たようなタスクに出くわすと、Hermes はそのファイルを直接呼び出す。あなたが改めて説明し直す必要はない。

このメカニズムをロブスターと対比すると、その違いは哲学レベルにまで及ぶ。

| | 🦞 ロブスターのスキル | 🐴 Hermes のスキル |
|---|---|---|
| 出どころ | **人手で記述**、ClawHub コミュニティから既製品をダウンロード | **AI が自動で記述**、あなたの実際のワークフローに基づく |
| 数量 | 13,000 本超、見知らぬ他人のスイスアーミーナイフ | 一本一本「あなたのために仕立てた」ナイフ |
| 成長 | あなたがインストールした分だけ、できることが増える | あなたが使うほど、自分で増えていく |

これこそが「使うほど節約できる」秘密だ——**繰り返される文脈は、一度だけ「学習」すればいい**。最初の一度はあなたが Hermes を連れて複雑なフローを一通り歩き、Hermes はそのフローをスキルに書き起こす。以降は同じ作業について、あなたが一句ずつ説明し直す必要はもうない。実測してみると、このメカニズムは最大 **90%** もの Token 費用を節約できる。ロブスターの健忘症があなたに毎日料金を払い直させる一方で、Hermes の記憶はあなたの投資を日々積み上げていく。

## サブエージェント：一頭のウマが、一つのチームへと分裂する

Hermes の二つ目の武器は、「サブエージェントの派生」だ。

Hermes はあなたのために独立した「サブエージェント（Sub-Agent）」を生み出し、同時に異なるワークフローを走らせてくれる。肝心なのは、これらのサブエージェントが飾り物ではないという点だ——

**各サブエージェントは、自分専用の対話コンテキスト、独立したターミナル、そして独立した Python RPC スクリプトを持つ。**

これは何を意味するのか。あなたはメインエージェントを「指揮官」に据え、同時に三頭のサブエージェントを送り出せるということだ。一頭はテストを走らせに、一頭はレポートをまとめに、一頭はあるデプロイを見張りに行く。互いにコンテキストは隔離され、汚染し合わないが、それでいて同じ指揮中枢に報告を上げる。一人分のワークフローが、並列に走る一つのチームへと展開されるのだ。

> 💡 珠玉のひとこと
> **ロブスターの成長は「アドオン」頼み、Hermes の成長は「分裂と沈殿」頼み。**
> 一方は他人が書き上げたツールを次々と身にまとっていき、広さは爆発的に増すが個体自体は賢くならない。もう一方は一度一度の経験を自分のスキルとして沈殿させ、さらにチームへと分裂させて並列処理する。前者はポケモン集めのようなもの、後者は自分で本を読む弟子を育てるようなものだ。**使えば使うほど、その差は広がっていく。**

## 好き嫌いのない胃袋：ローカルもクラウドも丸呑み

よくある誤解を一つ解いておきたい。多くの人が「ローカルモデルを動かせる」のはロブスターの専売特許だと思っているが、実はそうではない。

Hermes Agent も OpenClaw と同じく AI エージェントフレームワークであり、**どちらもローカルモデルと組み合わせて動かせるし、どちらもクラウド API に対応している**。

- **ローカルモデル**：Gemma、Llama 3 など。データは端末から出ず、プライバシーは自分の手の内にある。
- **クラウド API**：OpenAI、Claude、OpenRouter など。より強力な頭脳が欲しければ、いつでも切り替えられる。

つまり選択の決め手は、決して「モデルを動かせるかどうか」ではない——この問いは両者とも満点だ。本当の分水嶺は、ただ一つ。**一度タスクをこなした後、それを覚えているか、その経験を次の能力に変えられるか。**

## サンドボックスと権限を重視：セキュリティは設計であって、パッチではない

ロブスターのあの「ClawHub には毒が仕込まれているかもしれない」という懸念を覚えているだろうか。Hermes はこの点で正反対の道を選んだ。

複数の脆弱性が露呈し、コミュニティ製アドオンに悪意あるコードが潜むリスクを抱えていたロブスターと比べ、Hermes のアーキテクチャは**相対的に安全で、サンドボックス（Sandbox）と権限制御を重視している**。スキルが AI によってあなたのワークフローから自ら書かれ、管理されたサンドボックスの中で動くものであるなら、あの「一万三千人の見知らぬ他人のサプライチェーン」というリスクは、自然と収束していく。

これこそが、「ロブスターを捨ててウマを飼う」が冗談から一つの潮流へと変わったとき、その背後に実はきわめて理性的なトレードオフがあった理由だ。**ユーザーが求めているのは、決してより多くの爪ではなく、覚えていて、学ぶことができ、そして自分に噛みついてこない長期的なパートナーなのだ。**
