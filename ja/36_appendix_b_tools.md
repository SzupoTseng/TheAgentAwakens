# 付録B　オープンソースツール早見表

> 本書全体の300のシナリオで繰り返し登場するオープンソースツールを、職能別に分類し、「それが何であり／本書でどんな役割を担うか」を一言で添えた。括弧内は、百景のなかでロブスターが最も頻繁に呼び出す場面を示す。このリストそのものが、現代のSRE / FAツールボックスの縮図である。

## 可観測性（Observability）
| ツール | 一言での位置づけ |
|------|-----------|
| **Prometheus** | 時系列メトリクスの事実の源泉。本書では最も「自分自身で詰まらせる」（カーディナリティ爆発）こともあれば、最もアラートのトリガー源となることも多い |
| **Grafana** | メトリクスを人が読めるダッシュボードに描き出す。ロブスターがプッシュする「可視化トポロジー図」の多くはここに生える |
| **Loki / Tempo / Jaeger** | ログ（Loki）、トレース（Tempo/Jaeger）の三冊の帳簿。マイクロサービスのブラインドテストでの根本原因特定、Trace比較の主力 |
| **OpenTelemetry** | メトリクス／ログ／トレースを統一的に収集する標準。言語をまたいだ計装の共通言語 |
| **Thanos / Cortex** | Prometheusに長期ストレージとグローバルな視野を加える水平スケーリング層 |

## オーケストレーション、デプロイと自動スケーリング
| ツール | 一言での位置づけ |
|------|-----------|
| **Kubernetes（K8s）** | コンテナオーケストレーションのオペレーティングシステム。ほぼすべてのクラウドシナリオの土台 |
| **Argo Rollouts** | カナリア／ブルーグリーンデプロイのコントローラー。ロブスターが「微量の異常」を含むデプロイにブレーキをかける際に操作する対象 |
| **KEDA** | イベント駆動の自動スケーリング。FinOpsの「退勤制」スケールダウンの実行役 |
| **Argo CD / Flux** | GitOpsデプロイ。「Gitが唯一の事実の源泉である」を成立させる鍵 |

## ネットワークとサービスメッシュ
| ツール | 一言での位置づけ |
|------|-----------|
| **Istio / Linkerd / Envoy** | サービスメッシュとSidecarプロキシ。トラフィックの染色、mTLS、レート制限の実行層 |
| **Cilium** | eBPFベースのネットワークとセキュリティポリシー。秒単位でNetworkPolicyを下ろし、悪意あるPodを隔離する |
| **FRRouting（FRR）/ BIRD / ExaBGP** | オープンソースのBGPルーティングエンジン。ロブスターが「防御的な逆経路広告」を発動してトラフィックを取り戻す武器 |
| **RPKI / RIPE NCC API** | 経路起源の暗号学的検証。BGPハイジャックに対抗するコンプライアンスの基盤 |
| **Cloudflare** | エッジでのクレンジングとAnycastによる振り分け。天災／DDoS時のトラフィックの避難港 |

## 情報セキュリティとサプライチェーン
| ツール | 一言での位置づけ |
|------|-----------|
| **Falco** | eBPFベースのランタイム脅威検知。リバースシェルやランサムウェアの挙動に対する最初のホイッスルブロワー |
| **Wazuh** | ホストへの侵入検知とログ監査。ランサムウェアの「エントロピー急上昇」アラートの発生源 |
| **Trivy** | コンテナと依存関係の脆弱性スキャン。CVE発生時にリポジトリ全体をブラインドスキャンするスキャナー |
| **OPA Gatekeeper / Kyverno** | K8sのポリシー・アズ・コード（Policy as Code）。「こっそりリリース」された非準拠サービスを遮断する |
| **HashiCorp Vault** | 鍵と証明書の集中管理とローテーション。漏洩した鍵を秒単位でサーキットブレークする |
| **cert-manager** | K8s内の証明書発行と更新。mTLS／HTTPSを失効させない門番 |

## ストレージとデータ
| ツール | 一言での位置づけ |
|------|-----------|
| **Ceph / MinIO / Rook** | 分散オブジェクト／ブロックストレージ。本書でしばしば「容量が突如ゼロになる」被災者 |
| **Longhorn** | K8sネイティブの分散ブロックストレージ。スタック（Stuck Volume）解除の対象 |
| **PostgreSQL / MySQL / ProxySQL** | リレーショナルデータベースと読み書き分離プロキシ。デッドロック、レプリケーション遅延の主戦場 |
| **Redis** | インメモリキャッシュと分散ロック。クロックドリフトが引き起こす二重書き込み災害の主役 |
| **etcd** | K8sの頭脳（クラスタ状態ストア）。スプリットブレイン（Split-Brain）時に最も致命的な単一障害点 |
| **Elasticsearch / Logstash / Fluent Bit** | ログのインデックスとパイプライン。GDPR機密データのマスキングを注入する地点 |

## メッセージング、計算と回復力
| ツール | 一言での位置づけ |
|------|-----------|
| **Kafka** | 分散メッセージングのバックボーン。クラウドをまたいだ停電からの自己修復、ログの洪水のピークカットの中核 |
| **Spark / Flink** | ビッグデータのバッチ／ストリーム計算。データ偏り（Straggler）の発生地 |
| **Resilience4j / Sentinel** | サーキットブレーカーとレート制限のフレームワーク。「優雅な縮退」のコードレベルでの実装 |

## IaC、カオスとバックアップ
| ツール | 一言での位置づけ |
|------|-----------|
| **Terraform / Pulumi / Ansible** | インフラ・アズ・コード（IaC）。構成ドリフトを自動修正するPRの目標フォーマット |
| **Chaos Mesh / Litmus** | カオスエンジニアリングの注入フレームワーク。ロブスターの「緊急ブレーキ」で中止される対象 |
| **Velero** | K8sクラスタのバックアップとリストア。災害後の再建のセーフティネット |
| **Harbor** | プライベートコンテナイメージレジストリ。Docker Hubのレート制限時の予備のミラーソース |

> 🔍 手を動かす派への一言
> このリストのなかに「ロブスター専用」のツールは一つもない——どれも、あなたが**今まさに使っている、あるいはとっくに使うべき**成熟したオープンソースシステムだ。エージェントの価値はそれらを置き換えることではなく、**正しいタイミングで、正しいツールを呼び出し、正しい人々をつなぐ**ことを心得た、あの指揮官になることにある。まずツールボックスを揃えてこそ、エージェントは指揮すべきものを得る。
