# 第二篇　起動の儀式

# 第4章　一行のコマンドによる召喚：Linux から Windows ネイティブへ

## オープンソースの執事を、自分のコンピュータで飼う

手を動かす前に、まず一つはっきりさせておこう。Hermes Agent（そしてロブスター 🦞）の本質は、「**AI アシスタントを自分のコンピュータの中で飼えるようにするオープンソースツール**」である。あなたの対話履歴も、あなたのスキルも、あなたの記憶も、すべてあなた自身のマシンの中に保存される。どこかの会社のクラウドではない。これが「セルフホスト（self-hosted）」の核心となる精神であり、本書全体で語るすべての自動化が成り立つ前提でもある——**自分の環境の中で動いているからこそ、それは単なるおしゃべりではなく、本当にあなたの仕事を片付けてくれるのだ。**

## Unix 系環境：一行の curl で完了

**Linux、macOS、WSL2、Termux** 環境であれば、インストールは文字どおり「一行のコマンド」だ。ターミナルに公式のインストールスクリプトを貼り付ける。

```
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | sh
```

（コミュニティや公式ドキュメントでは、GitHub を直接指す等価なスクリプトもよく見かける：`https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh`。）

インストールが終わったら、一度ガイド付きセットアップを実行する。

```
hermes setup
```

これが、最も重要な二つの設定を一歩ずつ案内してくれる。**あなたの AI モデル**（ローカルの Ollama／Gemma／Llama にするか、クラウドの OpenAI／Claude にするか）、そして**あなたの通信プラットフォーム**（たとえばこれを Telegram につなぐ）だ。設定が終われば、いつでも待機していて、あなたのターミナルの中に住む執事が手に入る。

## Windows ネイティブ：ついに WSL2 の束縛から解放される

かつて Windows ユーザーがこの種のエージェントを飼うには、ほぼ必ず先に WSL2、Docker、あるいは Cygwin を入れる必要があり、敷居は低くなかった。**それはもう変わった。**

Nous Research 公式はすでに Windows プラットフォーム向けに作り直しを行い、これまでの文字エンコーディング（UTF-8）と Shell コマンドの互換性の問題を解決した。これにより、CLI、TUI のインタラクティブインターフェース、通信ゲートウェイ（Gateway）、そして「AI が自律的にスキルを書く」といった中核機能が、すべて **Windows 10／11 上でネイティブに、何の苦もなく起動できる**ようになった——**WSL2 も Docker も Cygwin も一切不要だ。**

最も簡単な道は二つある。

### 方法一・ターミナルからワンクリックでインストール（PowerShell）

**Windows Terminal** を開き（管理者権限は不要）、公式の Windows ネイティブ用インストールコマンドをコピー＆ペーストする。

```
iex (irm https://hermes-agent.nousresearch.com/install.ps1)
```

このスクリプトは、プログラムを自動的に `%LOCALAPPDATA%\hermes\` のパス配下に隔離してインストールし、必要な **Python と Node.js の独立環境**を自動で構成する。さらに軽量化された **PortableGit（約 45MB）**を内蔵しており、AI が生成した Shell コマンドをバックグラウンドで何の苦もなく実行するのに用いる。インストールが終わったら、PowerShell のウィンドウを開き直せばすぐに使える。

### 方法二・デスクトップ GUI（Hermes Desktop）

コマンドラインにまったく触れたくないなら、コミュニティと公式は **Hermes Desktop** も用意している——Windows 専用のインストーラーをダウンロードし、実行するだけだ。初回起動時、バックグラウンドで自動的に前述のスクリプトを呼び出し、必要な互換環境をすべて構成してくれる。その後は、美しいウィンドウインターフェース（WebUI）の中で、モデルの切り替え、AI の記憶の管理、スキルの追加を直接行えるようになる。

## ⚠️ 知っておくべき一つの小さな制約

Windows ネイティブ版の完成度はすでに非常に高いが、最初に表に出しておく価値のある、生来の違いが一つある。

**もしあなたの主な目的が、エージェントに「Windows システムを深く制御させ、ローカルの複雑なプロジェクトのコード依存を改変させる」ことであれば**——Windows のシステムパスは POSIX（Linux）環境とは生まれつき異なるため、AI が複雑なローカル自動化コマンドを実行する際に、時として微細なバグを踏むことがいまだにありうる。

そこで公式の助言はきわめて実務的だ。

| あなたの立場 | 推奨環境 | 理由 |
|---------|---------|------|
| 純粋な開発者（エージェントにコードを直させ、複雑なローカル自動化を走らせたい） | **WSL2** | ターミナル自動化とプロジェクト統合において最も滑らか |
| 日常ユーザー（通信執事、データ整理、クラウド API 連携） | **Windows ネイティブ** | すでに完全に十分で、非常に安定している |

> 💡 君の一言
> **インストールの敷居の崩壊は、しばしば機能そのものよりも、一つのツールの運命を決定づける。**
> 「自分でプログラムを書ける AI を飼う」ことが、「まず WSL2 + Docker の設定を覚える」から「PowerShell を一行貼る」に変わったとき、このツールの潜在的ユーザーは、数万人のエンジニアから、一瞬にして数億人の Windows ユーザーへと拡張される。技術の普及は、しばしばより賢いことで勝つのではなく、よりインストールしやすいことで勝つのだ。
